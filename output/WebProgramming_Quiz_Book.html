تبدیل نوع ضمنی (Type coercion)

منبع: Introduction to JS، اسلایدهای ۲۰ تا ۲۲
درسنامه

فرض کن یک مترجم خیلی مهربان داری که هر وقت دو نفر با زبان‌های متفاوت حرف می‌زنند، بدون اینکه کسی از او بخواهد، حرف یکی را به زبان دیگری ترجمه می‌کند. JavaScript دقیقاً همین کار را با نوع داده‌ها می‌کند و به آن Type coercion (تبدیل نوع ضمنی یا خودکار) می‌گوییم.

قانون عملگر +

اگر یکی از دو طرف + رشته (string) باشد، طرف دیگر هم به رشته تبدیل می‌شود و دو رشته به هم چسبانده می‌شوند (concatenation):

عملگرهای -، * و /

این عملگرها فقط معنای ریاضی دارند، پس JavaScript سعی می‌کند هر دو طرف را عدد کند:

عبارت نتیجه چرا؟
"5" - 1 4 رشته‌ی "5" به عدد ۵ تبدیل می‌شود
2 * "3" 6 ضرب فقط عددی است
true + true 2 true معادل ۱ است
null + 1 1 null معادل ۰ است
undefined + 1 NaN undefined به NaN تبدیل می‌شود
نکته

عملگر === هیچ تبدیلی انجام نمی‌دهد؛ برای همین "5" === 5 برابر false است. همیشه === را ترجیح بده.

دام تستی

[] == false برابر true است، چون [] اول به رشته‌ی خالی "" و بعد به عدد 0 تبدیل می‌شود و false هم 0 است. ولی if ([]) اجرا می‌شود، چون آرایه‌ی خالی truthy است!

یک تشبیه ساده

== مثل نگهبانی است که قبل از مقایسه، لباس هر دو نفر را عوض می‌کند؛ === مثل نگهبانی است که اگر لباس‌ها فرق داشته باشند، همان اول می‌گوید «یکی نیستند».

۱-۱تبدیل نوع ضمنی (Type coercion)

۱گزینه‌ی ۲آسان

وقتی یک طرف + رشته باشد، طرف دیگر به رشته تبدیل و الحاق می‌شود: "5" + "1" یعنی "51". گزینه‌ی ۳ عدد ۵۱ است نه رشته؛ گزینه‌های ۱ و ۴ جمع ریاضی را فرض کرده‌اند.

۲گزینه‌ی ۱متوسط

عملگرها از چپ به راست ارزیابی می‌شوند: 1 + 2 می‌شود 3 و بعد 3 + "3" می‌شود "33". در خط دوم از همان اول رشته داریم پس "123". در خط سوم ضرب اولویت دارد: 5 * "2" برابر 10 و "10" - 10 برابر 0.

۳گزینه‌ی ۳سخت

null در مقایسه‌ی == فقط با undefined (و خودش) برابر است و به عدد تبدیل نمی‌شود؛ پس null == 0 برابر false است.

۴گزینه‌ی ۳سخت

خط ۲ مجاز است چون const فقط انتساب دوباره را منع می‌کند نه تغییر محتوای شیء. خط ۳ مقدار undefined چاپ می‌کند. در خط ۴، user.address برابر undefined است و خواندن city از آن TypeError می‌دهد.
